# Deployment & Store Release — Web Scrolling Screenshot

## 1. Distribution Targets

1. **Local Developer Sideloading:** Unpacked `.output/chrome-mv3` directory loaded via `chrome://extensions` (Developer Mode) for manual QA across Phases 1–4.
2. **Chrome Web Store (Primary):** Clean `.zip` artifact generated by `wxt zip` in Phase 4.
3. **Microsoft Edge Add-ons (Secondary):** Same Chromium MV3 `.zip` package is compatible with Edge Add-ons.

## 2. Build & Packaging Pipeline

WXT handles manifest generation (`wxt.config.ts`), bundling, minification, and `.zip` creation:

```bash
pnpm check      # Must pass: lint + format:check + typecheck + vitest + build
pnpm test:e2e   # Must pass: Playwright Chromium MV3 suite
pnpm zip        # Produces .output/web-scrolling-screenshot-<version>-chrome.zip
```

**Package hygiene rules:**

- Production `.zip` must **exclude** source maps (`.map`), test fixtures, `docs/`, and dev-only files.
- Total `.zip` size budget: **< 1.5 MB**.
- Manifest version in `wxt.config.ts` / `package.json` follows SemVer (`1.0.0` for initial store release).

## 3. Chrome Web Store Submission Checklist (Phase 4)

- [ ] **Permissions review:** Verify built `.output/chrome-mv3/manifest.json` contains only `activeTab`, `scripting`, `offscreen`, `downloads`, `storage` (no `<all_urls>`, no `tabs`, no `debugger`).
- [ ] **Single-purpose statement:** Clear, concise description matching Chrome Web Store policy ("Capture full-page scrolling screenshots and custom selected regions at High-DPI resolution").
- [ ] **Permission justifications prepared** for the CWS review form (each permission mapped 1:1 to [`SECURITY.md`](SECURITY.md)).
- [ ] **Privacy practices tab:** Declare **zero data collected** ("We do not collect, transmit, or sell any user data") + host a static Privacy Policy page or repository `PRIVACY.md` link.
- [ ] **Store visual assets ready:**
  - `128×128 px` store icon
  - 3–5 localized screenshots (`1280×800 px`) demonstrating Full Page Capture, Drag-to-Select Region, Preview Zoom, and Arabic RTL UI
  - Small promo tile (`440×280 px`)
- [ ] **Clean install verification:** Unzip the exact submission `.zip` into a temp folder, load it via `chrome://extensions`, and smoke-test both Full Page and Region capture on a fresh Chromium profile before uploading.

## 4. Versioning & Release Workflow

- Bump version in `package.json` on a release branch (`release/vX.Y.Z`), update `CHANGELOG.md`, run full CI (`check` + `test:e2e`), tag `vX.Y.Z` after owner approval, and upload the CI-verified `.zip` manually in the Chrome Web Store Developer Dashboard (never commit store OAuth tokens or secrets to GitHub).
