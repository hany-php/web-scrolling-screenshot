لا تبدأ أي مرحلة جديدة إلا بعد اجتياز **بوابة الاختبار (Test Gate)** للمرحلة الحالية واعتماد المالك. تنتهي كل مرحلة بنسخة قابلة للتشغيل والتجربة داخل المتصفح.

### قواعد العمل لكل مرحلة

- تُنفذ كل مهمة في فرع مستقل `phase-<n>/<topic>` وتُدمج عبر Pull Request بعد نجاح CI.
- يتم تحديث مربعات المهام `[x]` في هذه الوثيقة ضمن نفس التغيير.
- تُشغَّل بوابة الاختبار آلياً، وتُعرض الأرقام الفعلية والنتائج على المالك مع لقطات/تجربة حية.
- أي خطأ يظهر لاحقاً يُكتب له اختبار ارتداد (Regression Test) قبل أو مع إصلاحه.

## المرحلة 1: محرك الالتقاط الكامل عالي الدقة (Phase 1: Full-Page High-DPI Engine)

**الهدف:** التقاط صفحة ويب طويلة كاملة بدقة `devicePixelRatio` الكاملة عبر تمرير ذكي ودمج في `OffscreenCanvas` مع تنزيل PNG فوري.
**اقرأ قبل البدء:** `docs/ARCHITECTURE.md`, `docs/adr/0002-capture-engine-offscreen-stitching.md`, `docs/TESTING.md`, `docs/SECURITY.md`

**المهام**

- [x] بناء وحدة حساب خطة التمرير (`scroll-planner.ts`) كدالة نقية: حساب خطوات `(x, y)`، القص الجزئي للشريحة الأخيرة، ومراعاة `devicePixelRatio`
- [x] معالجة مهلة المتصفح لـ `captureVisibleTab` (Rate-limit scheduler) مع إعادة المحاولة عند الحدود
- [x] حقن منسق التمرير في `capture-content.ts`: تعطيل `scroll-behavior: smooth` مؤقتاً، إخفاء `fixed/sticky` بعد الشريحة 0، تحفيز تحميل الصور الكسولة (`lazy-load`)، واستعادة حالة الصفحة بدقة
- [x] بناء `offscreen` Stitcher باستخدام `OffscreenCanvas` و `createImageBitmap` وتفريغ الذاكرة فور الدمج
- [x] دعم التقسيم الآمن للصفحات فائقة الطول (تجاوز 16,384px) إلى شرائح مرقمة بدون فقدان بكسل
- [x] ربط زر «التقاط الصفحة كاملة» في Popup مع عرض نسبة التقدم (0%–100%) وزر الإلغاء، وتنزيل PNG مباشر مبدئياً

**بوابة الاختبار (Test Gate)**

- [x] اختبارات Vitest لوحدة `scroll-planner` و `slice-splitter` على 1x / 1.25x / 1.5x / 2x / 3x DPR
- [x] اختبار Playwright E2E على صفحة طويلة (6,000px) تحتوي على Sticky Header: أبعاد الصورة الناتجة تطابق `(width * DPR) × (height * DPR)` مع عدم تكرار الـ Header
- [x] اختبار Playwright E2E على صفحة فائقة الطول (18,000px) يتحقق من التقسيم السليم بدون انهيار `OffscreenCanvas`
- [ ] مراجعة المالك لتجربة الالتقاط على 3 مواقع حقيقية متنوعة

## المرحلة 2: التقاط المساحة المحددة بالماوس (Phase 2: Drag-to-Select Region Capture)

**الهدف:** تمكين المستخدم من سحب مستطيل لتحديد أي جزء من الصفحة — حتى لو كان أطول من الشاشة — والتقاطه بدقة High-DPI.
**اقرأ قبل البدء:** `docs/ARCHITECTURE.md`, `docs/DESIGN-SYSTEM.md`, `docs/SECURITY.md`

**المهام**

- [x] بناء طبقة التحديد (`SelectionOverlay`) داخل `Shadow DOM` معزول تماماً عن CSS الصفحة المستهدفة
- [x] تنفيذ السحب بالماوس وتعديل الحجم لحظياً مع شارة الأبعاد (`W × H px`) وزر/اختصار إلغاء (`Esc`)
- [x] تنفيذ التمرير التلقائي (`Edge Auto-Scroll`) عند سحب المؤشر قرب الحافة العلوية أو السفلية لنافذة العرض
- [x] حساب حدود القص النسبية بالبكسل الفعلي وتمريرها لمحرك الالتقاط لدمج الشرائح ضمن نطاق التحديد فقط (عدم تصوير كامل الصفحة إذا كان التحديد صغيراً)
- [x] ربط زر «تحديد مساحة للتصوير» في Popup واختصار لوحة المفاتيح

**بوابة الاختبار (Test Gate)**

- [x] اختبارات Vitest لتحويل إحداثيات التحديد (Page coordinates → Tile crop rectangles) مع DPR مختلف
- [x] اختبار Playwright E2E: سحب منطقة داخل الشاشة + سحب منطقة تمتد عبر تمرير الصفحة (1,800px ارتفاعاً) والتحقق من دقة أبعاد الصورة الناتجة ومطابقتها للمنطقة المحددة
- [x] اختبار الإلغاء بزر `Esc` والتأكد من إزالة الـ Shadow DOM بالكامل دون أثر في الصفحة
- [ ] مراجعة المالك لتجربة السحب والتمرير التلقائي
